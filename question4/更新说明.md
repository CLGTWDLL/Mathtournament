# 第四问更新说明（2026-09-13）

本次更新提供第四问动态提前停止补充优化实验；论文正式主方案仍为 V5 / sparse / 29站稀疏骨架，动态方案不替代主方案。

## 1. 补充优化实验身份

- 论文正式主方案仍以 V5 / sparse / 29站三类42组本地配对为主证据；动态提前停止方案只提供40组均匀场景补充优化证据。
- 补充优化实验使用 `代码/动态骨架_v1/q4_dynamic_policy.Policy()`，即"29 站骨架 + 反馈驱动的后验概率提前停止"。
- 新算法仍然继承旧算法的代码（基础控制器类），**继承关系未改动**：`q4_dynamic_policy.Policy` → `q4_base_policy.Policy`（原 `q4_light_policy.Policy`）→ `q4_gdop_mpc_policy.Policy`。被继承的基础模块保留，不在删除范围内。

## 2. 12.5 米反馈几何层改为可选、默认关闭

新算法原本每步都对未解频道重算 12.5 米保守支撑域，用来"证明某频道不可能有源"从而提前关闭频道，并支撑严格可行域删站。40 局同种子实测：

| 指标 | 打开几何层 | 关闭几何层（现默认） |
| --- | ---: | ---: |
| 虚拟时间（逐局） | — | 与打开时 40/40 完全相同 |
| 动作序列（逐局） | — | 与打开时 40/40 完全相同 |
| 清除全部实际源 | 40/40 | 40/40 |
| 几何层实际关闭的频道数 | 0 | 不适用 |
| 平均进程 CPU 时间 | 29.81 s | 15.41 s（"删除版"批量）／13.18 s（串行 A/B） |

该层在均匀分布实例上从未触发（`dynamic_empty_channels = 0`，不存在证书类型只有 `posterior_remaining_below_threshold` 与 `sixteen_confirmed`），因此关闭它不影响正确率，只省计算量。接口保留：

```python
Policy(existence_stop_threshold=0.01, feedback_geometry=True)   # 需要严格删站时再打开
```

命令行对应 `run40_dynamic.py --feedback-geometry`。

## 3. 新补充优化实验算法与旧算法的同种子配对（本次更新的主要依据）

同一批 40 个候选种子（源数 10—16 各 5—6 例，均匀分布），逐局配对，单线程数值库。

| 指标 | 旧算法（29 站静态骨架） | 动态提前停止方案（补充） |
| --- | ---: | ---: |
| 平均虚拟时间 / s | 6328.33 | **6183.91** |
| 虚拟时间合计 / s | 253133.29 | 247356.45 |
| 平均进程 CPU 时间 / s | 15.41 | 与旧算法持平（串行 A/B：12.97 → 13.18） |

- 配对虚拟时间差：平均 **节省 144.42 s（2.28%）**，近似 95% Student-t 区间 [123.03, 165.81] s，不跨零；40 局中 35 局更短、5 局完全相同。
- 5 局相同全部是 16 个源的实例：确认满 16 个源后新旧两版走同一条路线，新算法不会触发概率停止。
- 只看触发概率停止的 35 局：平均节省 165.05 s（2.56%）。
- 40/40 局清除全部实际源。旧算法 40/40 通过确定性连续方向覆盖证书；新算法 35 局走概率停止（只做逐动作回放审计），5 局仍走确定性证书。
- CPU 使用同一进程内串行 A/B（4 个种子）核对，排除并发争用：旧 12.973 s → 新 13.181 s，平均 +0.207 s。

原始记录：`数据/对比40次/20260913-145508-pair40/`（`对比报告.md`、`comparison.json`、`cpu_ab_sequential.json`、`light/`、`dynamic/`、`nogrid-c1..c4/`）。

# 动态调整层说明

本目录是第四问当前（唯一）算法的实现目录。默认入口为 `q4_dynamic_policy.Policy()`，它在被继承的基础控制器（`q4_base_policy.Policy`，29 站静态骨架）之上增加"反馈更新后按后验概率提前停止"的动态层。

本次更新（默认算法切换、12.5 米几何层默认关闭、代码与数据增删）见 `../../更新说明.md`。

## 算法关系

基础控制器把 29 个后续站当作完整路线，必须走完才结束。动态层仍然把这条路线当作**初始**计划，只在反馈更新的时机判断能否提前收工：

- 默认采用 1% 的概率阈值。每次获得无信号反馈后，程序估计"至少还有一个未发现源"的后验概率；只有在确认至少 10 个源、且该概率不超过 1% 时，才停止访问剩余站点。
- 若确认源数达到 16，仍沿用基础控制器的确定性计数规则结束。
- 后验计算使用以下题设先验：总源数在 10—16 中等可能；给定总源数时各频道组合等可能；位置在半径 1800 米圆域内按面积均匀；接收半径在 1000—1500 米内均匀；全向源与定向源各占一半，定向朝向均匀。
- 连续参数用 16384 个固定 Sobol 样本积分。固定样本使同一输入可以重复得到同一结果，也避免策略读取模拟器种子或隐藏真值。

## 可选的 12.5 米反馈几何层

动态层最初还带一层反馈几何：每步对未解频道重算 12.5 米保守支撑域，支撑域为空或负反馈不足以覆盖时提前关闭频道（`feedback_geometry=True` 时还启用严格可行域删站）。40 局同种子实测它从未触发，虚拟时间与动作序列和关闭时逐局完全相同，CPU 时间却由 15.4 秒升到 29.8 秒，因此默认关闭，代码保留：

```python
Policy(existence_stop_threshold=0.01, feedback_geometry=True)     # 打开
python -B run40_dynamic.py --runs 40 --feedback-geometry           # 命令行打开
```

## 保证范围

概率停止表示：在上述先验和观测模型成立的条件下，程序估计"仍有未发现源"的概率不超过设定阈值。它不再提供确定性无遗漏证明，1% 也不是由有限次仿真直接证明的实际漏检率。

把 `existence_stop_threshold` 设为 `0` 或 `None` 可以关闭概率停止，恢复基础控制器的确定性结束条件；`strict_prune_interval` 默认为 `0`，因为严格可行域删站在现有真实实例中没有删掉任何站点，却显著增加计算时间。

程序分别记录：

- `truth_complete`：离线实验中是否清除了模拟器实际生成的全部源；
- `replay_audit`：逐动作独立回放是否一致；
- `strict_guarantee`：本次结束是否完全没有使用概率证书；
- `strict_certificate_audit`：是否执行并通过基础控制器的确定性证书审计。

## 小样本试验

覆盖真实源数 10—16、每档一例的同种子配对（结果保存在 `results/dynamic_pair_threshold_001_all_counts.json`，汇总在 `results/dynamic_pair_threshold_001_summary.json`）：

| 指标 | 结果 |
| --- | ---: |
| 配对数 | 7 |
| 清除全部实际源 | 7/7 |
| 触发概率停止 | 6/7 |
| 平均节省虚拟时间 | 136.52 s |
| 平均少移动 | 494.03 m |
| 平均少测量 | 6.43 次 |
| 平均少切换频道 | 5.57 次 |

16 个源的实例没有触发概率停止，新旧结果完全相同；其余六档均在清除全部实际源后提前结束。样本数只有 7，只能说明代码按预期工作，不能据此声称漏检概率已由实验校准。

对源数为 10、种子为 1480014 的实例做阈值敏感性检查：

| 阈值 | 是否概率停止 | 后验概率 | 节省虚拟时间 | 少访问的后续站 |
|---:|:---:|---:|---:|---:|
| 5% | 是 | 4.889% | 322.38 s | 2 |
| 1% | 是 | 0.569% | 198.25 s | 1 |
| 0.1% | 否 | 0.569% | 0 s | 0 |

三档在该实例中都清除了全部实际源。5% 更省时但承担更高模型风险；0.1% 在该实例中没有缩短路线。当前把 1% 作为折中默认值，写入论文时应同时报告先验假设、阈值和有限样本限制。

## 扩大样本后的对照

同一批 40 个候选种子（源数 10—16 各 5—6 例，均匀分布）上新旧逐局配对：新算法平均虚拟时间 6183.91 秒对旧算法 6328.33 秒，平均节省 144.42 秒（2.28%），近似 95% Student-t 区间 [123.03, 165.81] 秒，35/40 局更短、5 局相同，40/40 局清除全部实际源；CPU 时间与旧算法持平。原始记录在 `question4/数据/对比40次/20260913-145508-pair40/`。

## 运行方法

```powershell
python -B test_dynamic.py test_base_policy.py
python -B run40_dynamic.py --runs 40 --start 1480000 --out "..\..\数据\对比40次\新批次\dynamic"
python -B run40_dynamic.py --seeds 1480000 1480002 --out "..\..\数据\对比40次\新批次\dynamic_pair"
```

批量入口每次新建独立目录，不覆盖已有批次。运行只使用本地环境，未连接官方模拟器。
